# Alien's shared byte archive

The owner requested one cache containing Alien and its private Eye, temporary API text on the field, broader internal monologue, and feedback that values learning, growth, formulation and understanding. The owner then selected carrying learning and monologue history forward across restarts.

The canonical content file is `data/alien.cache` inside the installation's runtime `data/` directory. It is a versioned SQLite byte archive: bounded compressed BLOBs, immutable hash references, explicit content kinds, owner-only access, durable short transactions, and no executable deserializer. A temporary rollback journal may appear during a transaction. This is one content archive; provider credentials, settings, logs and quota accounting remain separate controls. Existing SVGs, sessions and release archives are preserved and are not silently migrated.

Each active world has a separate namespace and native integer timeline. Retained library material uses an explicitly reserved archive namespace, with original world/tick provenance. The library is not another Alien identity. Learned word transitions, recent formulation vocabulary, numeric expectations and public monologue references carry forward. Earlier thoughts can be retrieved with their original stamps. Historical material is not replayed as current input, and the time between launches is unknown. Raw Eye source states are fresh; retained drawings are snapshots, not full native checkpoints.

The unchanged native art composer runs transiently in RAM. Its actual output is rasterized into PNG bytes; those bytes and the generation specification enter the cache. No new SVG files are produced. The Eye receives that real cached PNG through the existing anonymous byte channel. Its full numeric perception, native drawing scene/retained marks and provenance are stored in the same cache. A separate receipt records whether an observation actually entered Alien at a native tick. Raw desktop screenshots remain transient and are not archived or uploaded.

Validated API response bytes are cached before their references enter accounting receipts. Once actually admitted, each response appears once as literal, wrapping text over the field, labelled with its unregistered source. It rolls away and fades. There is no main-window prompt box or permanent text panel; animation polling stops when the queue empties. The field's cells, colours, layers and native cadence are preserved. The GPU field capture observes the field; a desktop look can also see the temporary GTK text overlay.

Public monologue no longer cuts lines to56 characters or drops all but6 queued lines. A cache-backed FIFO survives native agent respawns, and the full formed/emitted text is retained. A bounded recent vocabulary and short association walks control CPU/RAM cost. Full text and individual learned associations remain in the archive. Idle/dream formulations use encountered vocabulary and learned transitions rather than only fixed sentence banks. Private thoughts keep their separate private path and never enter the API rolling display.

The feedback values have bounded effects on the native valuation gate. New supported transitions contribute growth; revisable numeric expectations contribute formulation; prediction improvement contributes learning and understanding. Predictions are scored on later observations before training on them, against both persistence and a running-mean comparison, after a minimum evidence window. World, segment, source, helper and epoch boundaries reset previous-observation links. API associations remain unverified, and generated monologue is not counted as external predictive evidence. These mechanisms do not establish factual truth, general understanding, neural-model training or consciousness. No additional paid model calls are introduced; the existing13 total attempts per rolling hour and owner stop control remain.

Published API/art/Eye references are flushed before cross-process delivery. Writes are batched in bounded RAM, with no writer transaction held between batches. Busy storage is surfaced rather than silently resetting an archive. Native and archive data close with the owned application processes. Promotion selects a new immutable next-launch release; an already-running world remains on its existing version.

Required saves wait briefly for an existing writer to finish. Opportunistic background batches use no lock wait and retain their pending bytes for a later attempt. This keeps ordinary HDD commit overlap from being treated as a failed publication while background admission remains responsive.
